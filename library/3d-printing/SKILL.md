# 3D printing

Use the shared workbench for versioned tools, reusable scripts and printer/material profiles. The user's only printer is the Bambu H2D; use it as the fixed print target across projects. Reuse means sharing the workflow and tools between projects. Keep model source, references, manufacturing requirements and generated evidence in the target project. A model is complete for the requested stage when its declared requirements have corresponding evidence or are explicitly reported as unresolved.

## 1. Establish the project and requirements

Read the project's applicable instructions, CAD README, Makefile and generators before changing anything. Preserve an existing CadQuery, Blender or build123d workflow unless the user requests a migration. For Hearth rack work, read [Hearth routing](references/hearth.md).

The workbench is `/Users/goberlec/personal/3dprinting`. Its [README](../../README.md) locates the pinned environment, profiles and scripts. Resolve this skill's real path before following relative links if installed through a symlink; locate the existing checkout if it moved.

For a new mechanical project without a workflow, use the workbench's locked build123d/b123d-print environment. Create a project-local `b123d-print.toml`, part source and reference/output directories using the installed CLI's help and template. Invoke the shared executable with an explicit `--root` for that project; keep dependency installation in the workbench.

Establish the requested artifact before selecting print settings:

- **CAD model:** retain editable source, named geometry/material bodies, logical material roles, plate grouping and intended print orientation. Export separate body meshes in a shared coordinate frame for native assembly. Material products, colours and hotend assignments may remain undecided when they do not affect design correctness; a printer-neutral 3MF is not required.
- **H2D print project:** generate a separate 3MF through Bambu Studio with complete resolved H2D material/process profiles, declared colours, logical-slot-to-hotend mapping, support and purge/tower settings. Use known project choices; if colours or hotend assignments are undecided, choose documented provisional values instead of blocking export with a questionnaire. Record any assumed material variant and qualify the slice by that profile; ask when the missing choice affects design correctness or a requested final print approval. Do not ask the user to select a printer. Separate material bodies do not require separate physical nozzles. Report verification for the declared setup and leave confirmation against the actual loaded filaments pending when necessary.

Before modeling, record dimensions and their sources, mating interfaces, intended fit, service loads/environment, known material constraints, intended bed face and outstanding physical tests. Leave undecided manufacturing settings explicit rather than blocking a reusable model on them. Use [requirements and design guidance](references/requirements.md) to distinguish modeled clearance, numerical verification tolerance and physical manufacturing tolerance. Ask about missing inputs when they affect design correctness; do not replace unknown hardware dimensions with undisclosed estimates.

## 2. Construct or remix

Model named parameters and derive features from those parameters. Keep printer compensation separate from nominal dimensions and intended clearance. Choose orientation and geometry together, considering load direction, bed contact, layer bonds, overhangs, support removal and critical surfaces. Set numerical design rules from the actual process and evidence, not universal FDM defaults.

For existing files, preserve originals and attribution. Prefer source edits when source exists, exact STEP operations for B-reps, and the project's mesh workflow for STL/3MF. Mesh conversion does not recover the original feature history or exact circles. Record which features must change and which must remain; verify both. Preserve separate material bodies in multicolor 3MF.

Record design material intent and user-reported successful prints in the existing project requirements, with their application and known conditions. Treat those observations as evidence for that scope; a helper's unsupported material combination is not proof of physical incompatibility. See [manufacturing intent](references/requirements.md#manufacturing-intent). For a concrete print project, match the selected product in its slicer profile. Geometry exports alone do not encode verified strength, fit or manufacturing intent. Fetch the actual product's primary datasheet/printing guidance when selection depends on temperature, moisture, creep, abrasion or mechanical properties; record the source and unresolved assumptions.

## 3. Verify geometry and inspect views

Run the project's own generator and checks. For b123d-print, use its native build/check, fit, orient and measure commands where applicable; read the installed help instead of recreating those functions. Explicitly review failed findings and warnings, including errors embedded inside successful MCP responses.

For exported STEP from any engine, use `tools/verify_step.py` with a project requirements JSON to independently check valid B-rep, solid count, dimensions/volume, material or empty probe boxes and selected wall sections. See [helper commands and limitations](references/tools.md). Use the project's native checks for assemblies, motion, mesh topology and multicolor body invariants; a STEP check is not a substitute for those checks.

Render the final exported file with `tools/render_model.py` or the project's native renderer. Inspect isometric/orthogonal views and sections through important features; check numerical evidence for dimensions and clearance. Rebuild dependent scenes after CAD changes. An image being generated is not evidence that an agent has inspected it.

## 4. Assess printability and prepare print projects

Assess bed contact, overhangs, bridges and orientation during construction and after removing a bed-facing surface. One connected solid with minimum Z=0 can still start large regions in mid-air. Use native geometry/orientation checks early; valid geometry alone does not establish printability. Inspect first layers, later islands/cantilevers and component/build transforms when trial-slicing. A diagnostic slice uses a declared temporary printer/process setup; keep it separate from the reusable model and qualify its findings by that setup.

For an H2D print project, read `profiles/printers/h2d-observed.json` and the saved slicer profiles. Use the exact Bambu material product and confirmed hardware; dated telemetry does not confirm the current spool, plate or calibration. Engineering Plate is preferred. Saved `petg` means PETG Translucent.

For new 3MF generation, use Bambu Studio's native `--load-assemble-list` with body meshes and plate/assembly assignments, complete resolved profiles, then `--slice 0 --export-3mf`. Follow [native H2D project generation](references/tools.md#native-h2d-project-generation). Let Bambu write the archive, transforms, profiles and purge metadata instead of constructing Bambu XML/ZIP or stamping profile IDs into a geometry export. Preserve the existing CAD engine and material bodies when replacing a custom packager. Verify the delivered archive by reloading and slicing it as well as inspecting it in Bambu; export success alone is insufficient.

For a concrete H2D slice of an already oriented STL or a named-part Bambu 3MF, use `tools/slice_bambu.py` with an explicit material, support policy and fresh output directory. The helper uses pinned Bambu Studio, checks emitted G-code settings and dimensions, verifies archive/G-code consistency, and records hashes. Copy and adapt a full resolved process profile in the project when different walls, infill or layer height are required. Check the resulting report, log, preview and toolpaths. `allowed` enables support but does not require generated support; `required` additionally requires support toolpaths; `forbidden` requires both support disabled and no support toolpaths.

For multicolour H2D print projects, declare every named part and logical filament slot, one colour/profile per slot and an explicit manual hotend map. The helper checks these against the source, exported project and G-code, including actual filament use. This helper currently accepts repeated slots of one filament product; for mixed products, including a user-proven combination, use native Bambu generation and its scoped evidence. For Hearth panels, preserve Blende/Schrift. Export complete selected profiles rather than empty profile IDs. Let Bambu calculate purge volumes from the supplied colours/profiles; do not ask the user for numerical purge volumes. Verify both H2D purge matrices and their multipliers, and enable/place the prime tower with emitted tower toolpaths for multicolour. If provisional choices change before printing, update the setup in Bambu, explicitly trigger purge recalculation and re-slice; slicing alone may reuse stored purge values. Keep native printable-area checks enabled. See [multicolour checks and commands](references/tools.md).

Evaluate overhang/bridge findings, support contact on functional surfaces, thin features, bed contact, warping risk and material preparation. Geometric sampling and a clean slice are evidence about the selected process, not proof of global minimum thickness or physical strength. Use `tools/calibration.py create` for a dimension/fit coupon with explicit reference-pin diameter, diametral clearances, thickness and physical dimensional tolerance. Slice the actual coupon with the intended process. Have the operator print and measure it, then evaluate the recorded dimensions and fit observations with `calibration.py evaluate`. Blank measurements remain pending; synthetic test observations are not physical validation. Use a project-specific coupon for interfaces this simple hole ladder does not reproduce. Never substitute an assumed calibration for a measured one.

While preparing a concrete print project, trial-slice each plate and capture Bambu's support-necessity warnings. When project requirements permit support and contact/removal is acceptable, persist support on the affected object in the derived print-project 3MF, then re-slice and verify actual support/interface paths and remaining warnings. With forbidden or unspecified support, leave the finding unresolved for an orientation/design decision. Follow the [object-specific support workflow](references/tools.md#support-detection-during-3mf-generation); the shared helper does not perform this retry automatically.

For a print-project delivery, open the final 3MF in Bambu Studio and inspect warnings and toolpaths on every plate. An empty warning field after enabling support is insufficient: Bambu skips this support-necessity check when support is enabled. Verify coverage beneath the flagged regions and removal access. Resolve zero-purge warnings and record prime-tower recommendations and any justified exception explicitly. The shared helper currently accepts one plate/one assembly; use the project's native workflow for multi-plate projects and report untested plates as unresolved. CLI success, image generation or a geometry-only roundtrip does not complete this check.

## 5. Deliver stage-specific evidence

List manufacturing acceptance requirements by ID in the existing requirements JSON. Bind them to named geometry, slicing or physical checks using `tools/verify_manufacturing.py`; see [evidence format](references/requirements.md). The helper checks current artifact, profile and measurement hashes. Missing evidence remains pending; changed files, wrong values and failed evidence cannot pass. A physical requirement names its actual specimen, so coupon results are not silently attributed to the finished part. Service loads or other claims without an implemented check remain explicitly unresolved.

Deliver source, requirements, reference attribution, the reusable model and inspected previews in the project. For print projects, also deliver the derived printer-specific files, slicing reports and effective profiles. State untested printers/plates and unresolved tests; the one-plate/one-assembly helper cannot verify an entire multi-plate model. Distinguish **geometry verified**, **slicing verified**, **needs review**, and **physically validated**. A failure or required review is not a print approval. Hashes bind reports to files; regenerate evidence after changing source or profiles.

Keep reusable helpers in this workbench and reference them here; project-specific generators/checks stay in their projects. Refresh saved profiles with `tools/prepare_bambu_profiles.py` only as part of a deliberate profile update.

Direct model-generation CLI calls execute project Python with caller permissions; the separately tested MCP sandbox does not apply to that path. These shared export helpers read model files rather than executing generator scripts. Uploading to a printer or starting a print requires a request covering that action. No global installation or MCP configuration is implied by using this skill.
